## What exists

- Data extraction — scripts/extract-data.js + scripts/validate-data.js, 119 checks green (phase 0, complete). Feature collection now also walks every kept class/subclass feature's text for ref* nodes (refClassFeature/refSubclassFeature) and pulls in the target, repeating until the set stops growing — class-features.json 279->302, subclass-features.json 465->786 (see docs/DATA.md, "Traps"). check-dangling-refs.js's new check verifies every ref* node (all four types) inside any feature's text resolves, including a D12 fallback so Fighting Style optionalfeature refs resolve against feats.json category "FS".
- Investigation script — scripts/investigate-slice1.js, confirms weapon mastery and fighting style data shape ahead of the remaining step-3 walkthrough work.
- Investigation script — scripts/investigate-class-skills.js, confirms all 13 classes' skill-choice shape in classes.json.
- Investigation script — scripts/investigate-subclass-shape.js, confirms subclass linkage, D28 filtering counts, and that every class grants a subclass at level 3.
- Investigation script — scripts/investigate-expertise.js, confirms the shape of expertise features and species skillProficiencies ahead of the expertise picker.
- Investigation script — scripts/investigate-expertise-2.js, confirms two more expertise-granting features not named "Expertise" (Ranger's Deft Explorer, level 2 not 1; Wizard's Scholar, restricted to 6 skills) and that "Infiltration Expertise" (Rogue/Assassin 9) grants no skill expertise at all despite its name.
- Investigation script — scripts/investigate-species-skills.js, confirms parent/variant inheritance (variant entries already carry their own, identical, skillProficiencies — nothing to merge), all element counts are 1, and five distinct entry shapes across the 26 species that carry the field (fixed single skill, fixed multi-skill, choice with count, choice without count, and `{ any: N }`).
- Investigation script — scripts/investigate-tool-proficiencies.js, confirms all 33 backgrounds carry toolProficiencies (always a 1-element array), three category keys occur (anyArtisansTool, anyMusicalInstrument, anyGamingSet, all count 1), and that items.json can filter all three structurally by item `type` code — anyMusicalInstrument's "INS" code also covers 15 magic instruments, so that filter additionally needs `rarity === "none"`.
- App skeleton — Vite + React + TypeScript, data served from public/data/.
- Markup renderer — src/markup/, 107 tests. Now also renders `abilityDc` (a save DC named for an ability score, e.g. Arcane Shot) as a sentence naming the ability, and `statblock` (a pointer to a creature/object statblock in another file) the same way as the ref* types — target name shown, tag/name/source kept in `data-ref-*` attributes since D7 still has no cross-file lookup.
- Feature-reference resolver — src/featureResolver/, a layer outside src/markup/ (D7 is unchanged: the renderer still shows only a ref*'s name with `data-ref-uid` on the element). `scanRefs`/`distinctRefs` find every refClassFeature/refSubclassFeature/refOptionalfeature/refFeat node in an entries tree at any depth (131 of 420 sit below the top level — list items, `options` blocks — not just directly in the array). `resolveRef` is a pure lookup against classFeatures/subclassFeatures (by the D33 `id` scheme) and optionalFeatures/feats (by name+source, with the D12 fallback to feats.json category "FS" for Fighting Style refs). `buildExpansions` resolves and recurses into the target's own text for further ref*s, one expansion per feature per branch (a `seen` set per recursion path prevents loops on a cycle). `<ResolvedEntries>` renders the untouched `<Entries>` output plus a collapsed `<details>` per resolved ref (a ref that doesn't resolve gets a visible "text not found" note instead, per D43 — never blank, never a crash). No shared data loader exists yet (D39 is not implemented — see docs/QUESTIONS.md), so `loadResolverData` fetches its four files independently, the same pattern every other `*Data.ts` module already uses. Wired into the three class-step components that render feature-shaped `Entries` content: SubclassPicker, FightingStylePicker, OptionalFeaturePicker.
- Storage layer — src/storage/, localStorage key `familliar:characters`, schema version 7. A saved character carries classSkills, speciesSkills, expertiseSkills, masteries, fightingStyle, (via CharacterClass.subclass) subclass, the background's two fixed skill proficiencies plus its tool proficiency (CharacterBackground.skillProficiencies / .toolProficiency), and optionalFeatureChoices — an array of `{ featureType, choices }`, so picks from more than one subclass progression could coexist without ambiguity. A version-6 save is rejected, not migrated (see docs/QUESTIONS.md, "Migrace uložených postav").
- Character creation wizard — src/creation/, steps: class → species → background → [expertise] → languages → ability scores → review. The expertise step only appears when the class grants Expertise by the chosen level — otherwise it is skipped and the remaining steps renumber to stay contiguous (`visibleSteps` in wizardState.ts). The class step also holds class skill proficiencies, weapon masteries, fighting style, subclass and optional-feature picks (D13) — all clear when the class or level changes, and all are now saved by the review step. The species step also holds the species' own skill proficiencies (fixed and/or chosen); they clear when the species changes. The expertise step's own selection clears whenever class, level, class skills, species, species skills, or background change (anything that affects the offered proficient-skill pool or the required count). The wizard's `subclass` field carries the chosen subclass's source and featureType alongside its name (SubclassChoice in wizardState.ts), computed once when the subclass is picked, so nothing needs to re-derive the subclass's book by loading the subclass list a second time.
- Five creation pickers — src/classes/, src/abilities/, src/species/, src/backgrounds/, src/languages/.
- Class skill picker, species skill picker, mastery picker, fighting style picker, subclass picker — src/classSkills/, src/speciesSkills/, src/masteries/, src/fightingStyle/, src/subclass/, wired into the class/species steps. Class skill picker receives the background's two fixed skills as disabledSkills (D18) once a background is chosen. Species skill picker receives the class skills and (if already chosen via back-navigation) the background's fixed skills as disabledSkills. The background step now also annotates its own two fixed skills when they collide with class or species skills already chosen (D44) — species is picked before background in the wizard order, so this is the only place that collision can surface. subclassData.ts's SubclassOption now also carries `featureType` (the subclass's own optionalfeatureProgression code, or null), read off the same classes.json fetch already made for the subclass list. The class/feature join in subclassData.ts now tries strict classSource matching first and falls back to className+subclassShortName+subclassSource (ignoring classSource) when that finds nothing — fixes 26 of 94 offered subclasses (e.g. Arcane Archer, Cavalier, Samurai, Rune Knight) that were rendering with no feature text because their text is filed under an older classSource than the XPHB-converted subclass entry (D27). All 94 offered subclasses now resolve at least one feature.
- Optional-feature picker — src/optionalFeatures/, one generic picker for every subclass's `optionalfeatureProgression` (Battle Master's Maneuvers, Rune Knight's Runes, Arcane Archer's Arcane Shot, College of Swords' Fighting Style — the four found by the earlier investigation). `FS:*` codes resolve against feats.json category "FS" (D12); every other code resolves against optional-features.json. Wired into the class step, shown once a subclass is chosen; clears when class, level or subclass changes; now persisted to storage.
- Tool proficiency picker — src/toolProficiencies/, wired into the background step. A named tool (e.g. "Disguise Kit") auto-fills with nothing to pick, matching BackgroundGrants' own display; a category choice (anyArtisansTool, anyMusicalInstrument, anyGamingSet) lets the player pick exactly 1 from a list filtered structurally out of items.json. The background step cannot advance until this choice is made. Persisted as `CharacterBackground.toolProficiency`.
- Expertise picker — src/expertise/, its own wizard step between background and languages, shown only when the class grants Expertise by the chosen level. The per-feature skill count isn't structured in class-features.json, so it's hardcoded in expertiseData.ts from PHB 2024 prose: features named "Expertise" (Bard 2/9, Ranger 9, Rogue 1/6) grant 2, unrestricted; "Deft Explorer" (Ranger 2) grants 1, unrestricted; "Scholar" (Wizard 2) grants 1, restricted to 6 named skills. "Infiltration Expertise" (Rogue/Assassin 9) is excluded — despite its name it grants no skill expertise (Masterful Mimicry, Roving Aim). The picker only ever offers skills the character is already proficient in, unioned from class skills, the background's fixed pair, and species skills; if that pool is smaller than the count calls for, it offers everything available and says so rather than blocking.
- Component tests — jsdom + Testing Library, e.g. src/creation/CharacterWizard.test.tsx.
